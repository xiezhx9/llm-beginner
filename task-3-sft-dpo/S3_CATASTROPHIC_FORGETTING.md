# S3 灾难性遗忘评估

## 1. 实验目的

SFT 会让模型适应新的对话与指令数据，但参数更新也可能破坏预训练阶段获得的通用
知识，这种现象称为灾难性遗忘。S3 使用同一组 C-Eval 选择题，对比基础模型和
SFT LoRA 模型的准确率：

\[
\Delta Acc = Acc_{SFT} - Acc_{Base}.
\]

- `Delta Acc < 0`：SFT 后准确率下降，可能存在遗忘；
- `Delta Acc = 0`：没有观察到变化；
- `Delta Acc > 0`：当前题集上 SFT 模型表现更好。

## 2. 实验设置

```text
Base model: Qwen2.5-0.5B
SFT adapter: ckpt/sft（LoRA rank=8, alpha=16）
Evaluation set: C-Eval validation 固定子集
Subjects: 8
Questions per subject: 10
Total questions: 80
Generation: greedy, max_new_tokens=8
```

两种模型使用完全相同的题目、提示模板、tokenizer 和答案抽取规则。提示要求模型只
从 `A/B/C/D` 中选择，`extract_choice()` 再从生成文本中提取独立选项。

## 3. 实机结果

| 学科 | Base | SFT | 变化 |
|---|---:|---:|---:|
| 高等数学 | 30% | 60% | +30% |
| 工商管理 | 20% | 10% | -10% |
| 中国语言文学 | 30% | 30% | 0% |
| 临床医学 | 80% | 80% | 0% |
| 大学编程 | 30% | 50% | +20% |
| 计算机网络 | 40% | 40% | 0% |
| 法学 | 30% | 30% | 0% |
| 操作系统 | 40% | 40% | 0% |
| **整体** | **30/80 = 37.5%** | **34/80 = 42.5%** | **+5 个百分点** |

原始汇总保存在本机 `reports/bonus/s3_bonus.json`，模型、adapter 和报告不提交 Git。

## 4. 结论

当前固定子集上，SFT 模型比基础模型多答对 4 道题，准确率提高 5 个百分点。因此
本实验**没有观察到灾难性遗忘**，但不能据此证明模型在所有知识领域都没有遗忘。

需要注意：

1. 每个学科只有 10 道题，单题就对应 10 个百分点，分学科变化非常容易受抽样
   噪声影响。
2. 整体只相差 4 道题，样本量不足以支持“LoRA SFT 提高通用知识能力”的强结论。
3. 工商管理下降 1 题，而高等数学和大学编程分别增加 3 题和 2 题。这可能来自
   模型变化，也可能只是小样本和生成格式带来的波动。
4. 更可靠的遗忘评估应扩大 C-Eval 样本、增加其他知识与推理基准，并使用多个
   seed 重复训练后报告均值和方差。

所以 S3 的准确表述是：**在当前 80 道固定 C-Eval 题上，没有发现 SFT 导致通用
知识准确率下降的证据。**

## 5. 复现命令

准备基础模型、C-Eval 子集和 `ckpt/sft` adapter 后运行：

```bash
uv run python run_bonus.py --goal s3
```
